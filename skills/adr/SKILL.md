# Architecture Decision Records

Use ADRs for decisions that affect structure, compliance, long-term operations, or costly reversibility. Do not create an ADR for ordinary implementation detail.

1. Read repository guidance and existing ADRs.
2. Confirm the decision and material alternatives.
3. Draft status, date, context, decision, alternatives, consequences, risks, compliance implications, and references.
4. Preview the complete document and obtain approval before writing.
5. Store it as `docs/adr/NNNN-short-title.md`.

Keep accepted decisions concise and implementation-testable. Use [promotion mechanics](references/promotion.md) when a repository decision should become toolkit-wide.
